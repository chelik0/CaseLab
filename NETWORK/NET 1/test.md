**Инкапсуляция и PDU**  
  
Инкапсуляция - процесс, при котором при передаче данных вниз по стеку каждый уровень добавляет к данным свою служебную информацию.  
  
PDU:  
  
Канпальный - кадр (Frame)  
Сетевой - пакет (Packet)  
Транспортный - сегмент (TCP) или датаграмма (UDP)  
  
**MAC и IP**  
  
MAC-адрес - идентифицирует сетевой интерфейс на канальном уровне и используется для доставки кадра внутри локального сегмента.  
IP-адрес - используется для логической адресации и маршрутизации между сетями.  
  
Оба нужны, потому что IP определяет, в какую сеть и к какому узлу нужно доставить данные, а MAC обеспечивает передачу кадра на конкретном локальном участке.  
  
  
**Как узел определяет другую подсеть**  
  
Хост сравнивает свой IP-адрес и адрес назначения с использованием маски подсети.  

Если сеть назначения отличается от его собственной, хост понимает, что получатель находится в другой подсети. Тогда он отправляет кадр на MAC-адрес шлюза по умолчанию, а IP-адрес назначения в пакете остается адресом конечного получателя.  
  
**ARP**  
  
Хост знает IP-адрес, но ему нужен MAC-адрес следующего узла.ARP-запрос отправляется как broadcast: «Кому принадлежит IP X.X.X.X? Сообщите свой MAC».  
  
В запросе:  
  
MAC отправителя - известен;  
 IP отправителя - известен;  
 IP получателя - известен;  
 MAC получателя - неизвестен.  
  
Запрос идёт на FF:FF:FF:FF:FF:FF, поэтому его получают все устройства в VLAN.  
  
ARP-ответ отправляет нужный узел уже неизвестному отправителю, потому что его MAC-адрес из запроса ему известен.  
  
**L1, L2 и L3**  
  
L1 передает биты в виде электрических, оптических или радиосигналов. Здесь нет MAC/IP-адресов.  
L2 работает с кадрами и MAC-адресами. Основная задача - доставка внутри локальной сети/VLAN.  
L3 работает с IP-пакетами и выбирает путь между разными сетями.  
  
**Способы подключения к оборудованию**  
  
Основные способы : 
Console - физическое локальное подключение;
SSH - удалённое защищенное управление;
Telnet - удаленное управление без шифрования, 
иногда Web/HTTP(S) и другие средства управления.  
  
Для первоначальной настройки из коробки обычно используется Console, потому что сетевые параметры для удалённого доступа еще не настроены.  
  
В продуктивной сети лучшая практика SSH, потому что трафик управления шифруется. Telnet использовать не следует.  
  
**enable secret и enable password**  
  
enable secret хранит пароль в защищенном виде и имеет приоритет над enable password.  
  
enable password — устаревший вариант и при определённых настройках может храниться практически в открытом виде.  
  
Поэтому для привилегированного режима используют `enable secret`.  
  
**Что означает конфигурация**  
  
line vty 0 4 - настраивает виртуальные терминальные линии VTY 0–4, то есть линии для удаленных подключений к устройству.  
password 7 - задает пароль для этих линий; число `7` означает, что значение записано в конфигурации в формате Cisco Type 7.  
08255F4A0F0A0111 - зашифрованное/обфусцированное представление пароля в формате Type 7.  
  
 **Зачем hostname и domain name перед RSA**  
  
При генерации RSA-ключей Cisco обычно использует имя устройства  доменное имя для формирования идентификатора устройства, который становится частью параметров RSA-ключа.  
Если hostname или domain name не заданы, генерация RSA-ключа может завершиться ошибкой, потому что устройству не из чего сформировать требуемое доменное имя/идентификатор.  
  
**Иерархическая модель сети**  
  
Иерархическая модель разделяет сеть на уровни с разными задачами:  
  
Access — подключение конечных устройств;  
Distribution — агрегация, политики, маршрутизация;  
Core — быстрая передача трафика между крупными частями сети.  
Collapsed core — объединение функций Core и Distribution в одном уровне/наборе устройств. Его используют, например, в небольших и средних сетях, где отдельный полноценный core был бы избыточен.  
  
**Домен коллизий и широковещательный домен**  
  
Домен коллизий — область, в которой устройства могут столкнуться при одновременной передаче данных.  
Broadcast domain — область, в которую распространяется широковещательный кадр.  
  
При переходе:  
  
Hub → Switch → Router  
  
Hub - все порты находятся в одном collision domain и одном broadcast domain.  
Switch - каждый порт обычно становится отдельным collision domain, но все порты одного VLAN остаются в одном broadcast domain.  
Router -  каждый интерфейс является границей broadcast domain; маршрутизатор не пересылает обычный L2 broadcast между интерфейсами.  
  
**Кадр с неизвестным MAC назначения**  
  
Коммутатор сначала смотрит MAC-адрес назначения:  
  
1C:2B:3B:4B:5C:6C  
  
Он ищет его в своей MAC address table. Если адрес есть — кадр отправляется только через соответствующий порт. Если адреса нет — коммутатор делает неизвестным: отправляет кадр через все порты этого VLAN, кроме того, откуда кадр пришёл. Если получатель ответит, коммутатор сможет изучить его MAC-адрес и порт.  
  
**VLAN**  
  
VLAN — логическое разделение одной физической коммутируемой сети на несколько отдельных L2-сетей. Например, можно сделать VLAN для сотрудников, гостей и телефонии. Устройства разных VLAN не находятся в одном broadcast domain и для общения между ними нужна маршрутизация.Стандарт тегирования — IEEE 802.1Q.  
  
**Почему VLAN до 4096**  
  
В поле VLAN ID в стандарте 802.1Q используется 12 бит: 2¹² = 4096 значений, то есть 0–4095.  
Но не все они используются как обычные VLAN. Классически:  
  
VLAN 0 — не обычный VLAN; используется для приоритета, при этом идентификатор VLAN не указывает на конкретный VLAN;  
VLAN 1 — стандартный VLAN по умолчанию;  
VLAN 4095 — зарезервирован.  
  
Для обычных VLAN используются значения 1–4094, хотя отдельные значения/диапазоны могут иметь специальные назначения в конкретной реализации.  
  
**Добавление и снятие VLAN-тега**  
  
На trunk-порту кадры между коммутаторами обычно передаются с тегом 802.1Q, чтобы принимающее устройство понимало, к какому VLAN относится кадр.  
  
На access-порту конечному устройству кадр обычно передается без VLAN-тега.  
access: тег обычно снимается перед отправкой конечному устройству;  
trunk: тег передается между сетевыми устройствами.  
  
**Native VLAN**  
  
Native VLAN — VLAN на 802.1Q trunk, кадры которого передаются без тега.Он нужен для обработки нетегированных кадров на trunk-соединении и совместимости с определенными сценариями.  
Оставлять native VLAN по умолчанию нежелательно: это может создавать проблемы с безопасностью и облегчать некоторые виды VLAN hopping/ошибочной передачи трафика. Обычно native VLAN меняют на отдельный неиспользуемый VLAN и согласованно на обоих концах trunk.  
  
**Зачем L2-коммутатору IP и default gateway**  
  
IP-адрес самому коммутатору нужен не для обычной L2-коммутации, а для управления самим устройством — например, чтобы подключиться к нему по SSH.  
Default gateway нужен, чтобы сам коммутатор мог обращаться к устройствам управления, находящимся в другой подсети.  
  
Например, если коммутатор имеет IP 192.168.10.2/24, а администратор находится в 192.168.20.0/24, коммутатор отправит ответ через default gateway.  
  
  
**Таблица маршрутизации и connected-маршруты**  
  
Таблица маршрутизации содержит информацию о том, через какой интерфейс или следующий hop отправлять пакеты к различным сетям.  
  
Маршруты могут появляться из: directly connected сетей; статических маршрутов; динамических протоколов маршрутизации.  
  
Connected-маршрут появляется автоматически, когда L3-интерфейс настроен с IP-адресом и маской и находится в рабочем состоянии.  
  
Многоуровневый коммутатор без ip routing не выполняет полноценную маршрутизацию между SVI. SVI с IP-адресами сами по себе ещё не означают, что устройство будет пересылать пакеты между VLAN. Команда ip routing включает функцию L3-маршрутизации.  
  
**Default gateway**  
  
Шлюз по умолчанию — устройство, которому хост передает пакеты, когда адрес назначения находится не в его локальной подсети.   
Если шлюз вообще не задан, хост сможет нормально общаться со своей локальной подсетью, но не сможет отправлять трафик в другие подсети.  
  
Если указан адрес шлюза из чужой подсети, хост не сможет корректно использовать его как gateway, поскольку gateway должен находиться в той же локальной IP-подсети, что и сам хост.

**SVI показывает up/down**  
  
Для SVI состояние up/down означает, что сам интерфейс VLAN существует, но его line protocol не поднят.  
  
Возможные причины:  
VLAN не существует;VLAN неактивен;нет ни одного активного физического порта, принадлежащего этому VLAN;порты VLAN находятся down;VLAN не проходит по trunk;при соответствующей конфигурации нет активного L2-соединения, которое позволяло бы VLAN считаться operational.
